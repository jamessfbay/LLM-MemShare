# Roadmap

The target is mature, self-hosted, multi-tenant memory middleware with a stable API, predictable operations, and evidence-backed isolation. The current release is a 0.2.0 beta foundation, not a finished production platform.

1. **Multi-tenant core — delivered.** Rust service, versioned migrations, operator tenant provisioning, user/service/agent lifecycle, workspace/project membership, credential rotation, explicit grants, memory CRUD and history, stable cursor pagination, leased handoffs, idempotency, RLS, embedded OpenAPI, CI, and two-tenant PostgreSQL tests are implemented. Proposal/review workflows, representative legacy-migration fixtures, and the complete policy matrix remain open.
2. **Operational beta — in progress.** Tenant row quotas, per-credential fixed-minute request limits, administrator queries, a verifiable per-tenant audit hash chain, process-local metrics, a native three-process verifier, dependency/coverage gates, and checksummed release artifacts with SBOM and provenance are implemented. Ownership transfer, hard deletion and retention, backup/restore with deletion replay, persistent metrics, measured capacity, load/soak testing, and independent security review remain required.
3. **Retrieval and clients.** The in-crate Rust client covers memory and handoff flows. Next work is route-complete Rust coverage, one widely used client language, measured keyword retrieval, optional derived vector search with an outbox and reauthorization, and reproducible quality/latency benchmarks.
4. **Verified adapters.** MCP 2025-06-18 and A2A 0.2.6 method subsets are available through the native authorization path. Full protocol conformance, external client fixtures, streaming/session capabilities, and broader compatibility remain future work. The core continues to operate without model inference, provider sessions, or vector services.
5. **Production candidate and 1.0.** The beta governance, support, and compatibility baseline is published. Stable 1.0 support/deprecation windows, upgrade/rollback and recovery evidence, broader artifact/platform coverage, security-review remediation, and independent deployment reproduction remain.

The detailed dependencies, acceptance gates, and non-goals are in the [implementation plan](IMPLEMENTATION_PLAN.md). Features move to “implemented” only when code, automated evidence, and accurate operator documentation land together.
